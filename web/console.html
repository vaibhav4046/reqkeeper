Thesis The seam Refusals Settlement Agent surface

An agent retries.
A retry is a second payment.

Retrying is the defining property of an agent harness. When the thing being retried moves money, nothing in the stack owns the duplicate. ReqKeeper owns it at the one place it can be owned: the seam between the agent and the signer.

Why Request Network

The invoice is the idempotency key. Every Request invoice carries a canonical request id and a payment reference embedded in the calldata — a stable obligation identity issued by an external system. It survives a wallet change, a key rotation, a re-import, regenerated calldata, and the 24-hour replay expiry. We did not invent an identity scheme.

And the loop closes without fabrication: pay with the reference embedded and Request's own payment detection flips the invoice to paid. SETTLED requires both an independently read receipt and the source's own verdict.

The approved bytes are not the signed bytes

Request hands you finished calldata. KeeperHub will not send finished calldata. Something has to bridge that, and whatever bridges it is where a payment can quietly change meaning.

Probed, not assumed

contract-call, data      -> HTTP 400 {"error":"Missing required field","field":"functionName"}
contract-call, callData  -> HTTP 400 {"error":"Missing required field","field":"functionName"}
raw route                -> HTTP 400 {"error":"Invalid action type: raw"}
transaction route        -> HTTP 400 {"error":"Invalid action type: transaction"}

The only write surface is (contractAddress, functionName, functionArgs), re-encoded on KeeperHub's side against an ABI it resolves itself. So between "the human approved these bytes" and "the signer signed these bytes" sits a decode, a transport, and a re-encode performed by the execution platform.

The named call survives only as an inner payload: a 65-byte signature, then the selector and its arguments. (to, data) as approved appears in no transaction anywhere.

What ReqKeeper does about it

Decode the approved calldata, re-encode it locally, and dispatch only if the result is byte-identical. Anything else refuses before a single network call.

Smuggled variantRefusal
trailing bytes appended after the argumentscalldata_mismatch
a selector not on the allowlistselector_not_allowed
dirty high bytes packed above an addresscalldata_mismatch
The codec refuses every type it does not implement. A codec that silently mis-encodes an argument is worse than none, because it fails the byte-comparison that was supposed to be the safety net. Its correctness is checked against KeeperHub's own encoder output — two independent implementations, same 260 bytes.

Honest limits

    
    
      
  • Duplicate protection is deployment-scoped. It cannot stop an independent wallet or a human paying the invoice out of band.
    • 
      
  • No semantic dedup across request ids. Two ids may mean the same real-world invoice.
    • 
      
  • Revocation is not an onchain undo. Already-broadcast work completes.
    • 
      
  • The audit trail is tamper-evident, not tamper-proof. It is not blockchain evidence and is not described as such.
    • 
      
  • No prompt-injection detection. A guarded signer enforces a declarative policy; it does not detect injection.
    • 
      
  • Sepolia only. Mainnet is disabled in code, deliberately.
